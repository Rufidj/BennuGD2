# DMDE Log Viewer

Small Python GUI to inspect DMDE scan logs, recover folder structure metadata,
and export a manifest we can later use for automated recovery.

This tool is intentionally conservative:

- It does not write to the source disk.
- It only parses log text files.
- It builds a browsable tree of folders/files when the log contains paths.

Current status:

- Opens a DMDE text log or exported text report.
- Opens an exported manifest JSON generated by this tool.
- Uses heuristics to detect file and folder paths from raw lines.
- Shows the recovered tree in a GUI.
- Lets you filter by text and export a JSON manifest.
- Auto-detects the connected source device from the DMDE log when possible.
- Can extract pseudo raw findings directly from a selected `/dev/...` device as `.bin` fragments.
- Detects probable file types automatically from the selected `/dev/...` source when the raw-scan log is loaded and accessible.
- Detects basic file signatures during extraction and saves fragments with a probable extension when possible.
- Can analyze an existing folder of extracted fragments and annotate matching pseudo records by offset/size.
- Keeps the raw source lines attached to each parsed entry.
- For DMDE Full Scan / Raw Scan state logs without plain paths, builds a synthetic tree
  with metadata, enabled signatures, and parsed block groups.
- Derives pseudo raw findings from block groups with offset and estimated size.
- Exports the parsed scan summary to CSV.
- Exports pseudo raw findings to a dedicated JSON file.
- Lets you filter recovery candidates by practical categories (Videos, Imagenes, Documentos, Comprimidos, Desconocidos) and minimum size.
- Ranks pseudo raw findings and exposes a `Top Candidates` view per block group.
- Builds a recovery-oriented library grouped by detected type (Videos, Imagenes, Documentos, Comprimidos, Desconocidos).

What still needs a real sample log:

- Byte-accurate extraction directly from the original disk or image.
- Robust parsing of DMDE-specific offsets/cluster references.
- Bulk recovery orchestration from saved scan metadata.

## Run

```bash
python3 tools/dmde_log_viewer/app.py
```

## Suggested workflow

1. Open your DMDE scan log.
2. Check whether the tree contains the folders/files you expect.
3. If the log really contains paths, choose the source root.
4. Select folders/files and use `Recover Selected`.
5. Export a JSON manifest for later sessions if useful.
6. Share a small redacted sample log if you want the direct recovery layer added.

If the file is a DMDE Full Scan / Raw Scan state log:

1. Open the log.
2. Browse `Scan Summary` in the tree.
3. Inspect `Enabled Signatures` and `Block Groups`.
4. Inspect `Pseudo Raw Findings` for offsets and estimated spans.
5. Export the parsed summary as CSV if needed.
6. Export findings JSON if you want to process pseudo records outside the GUI.
7. Use the recovery category selector and `Min size bytes` to narrow useful results quickly.
8. Check `Top Candidates` under each block group to review the highest-scoring pseudo findings first.

Note:

- If the app can infer the connected `/dev/...` device from the log, it will try to verify probable types automatically when the raw log is loaded.
- If you choose a connected `/dev/...` device without mountpoint and extract pseudo raw findings,
  the app can save the estimated byte ranges directly into fragments with a probable extension when detected.
- Path-based recovery with original names/folders still expects a mounted filesystem path.

Recommended filters:

- `Mostrar = Videos` and a medium `Min size bytes` to focus on media fragments first.
- `Mostrar = Imagenes` for image-like candidates.
- `Mostrar = Desconocidos` when you want to inspect everything that was not classified yet.

## Important limitation

Some DMDE files, especially raw scan-state logs, do not contain plain file or
folder names. In that case the tool can load the file but cannot reconstruct a
tree because the data is encoded as internal scan metadata rather than paths.
